# Мои заметки по Java Backend

Это моя рабочая база знаний по Java Backend-разработке. Я собираю здесь понятные объяснения, команды, примеры кода и практические заметки, к которым могу возвращаться во время учёбы и работы над проектами.

Я использую материалы как справочник: разбираю тему, повторяю примеры, запускаю команды и дополняю конспекты собственными выводами. Это не попытка перечислить технологии в резюме, а инструмент для системного обучения и практики.

## Как устроены заметки

В большинстве тем я придерживаюсь такой структуры:

- **Что это** — объяснение термина простыми словами.
- **Зачем нужно** — какую задачу решает технология или подход.
- **Как работает** — важные детали и ограничения.
- **Примеры** — команды и фрагменты кода с пояснениями.
- **Частые ошибки** — что важно учитывать на практике.
- **Практика** — задания, которые я могу выполнить самостоятельно.

## Как я работаю с материалами

1. Изучаю тему и разбираюсь в основных понятиях.
2. Закрываю шпаргалку и объясняю материал своими словами.
3. Повторяю команды или пишу код самостоятельно.
4. Изменяю пример: добавляю условие, обрабатываю ошибку, проверяю граничные случаи.
5. Если что-то остаётся непонятным, записываю вопрос и ищу ответ в официальной документации.
6. Отмечаю тему освоенной только тогда, когда могу применить её без копирования и объяснить своё решение.

Прогресс я отмечаю в [TRACKER.md](TRACKER.md). Идеи для практики собраны в [PROJECTS.md](PROJECTS.md), официальные источники — в [RESOURCES.md](RESOURCES.md). Для быстрого повторения использую [QUICK-REFERENCE.md](QUICK-REFERENCE.md).

## Мой подход к обучению

Я стараюсь не ограничиваться знанием названий технологий. Для меня важно уметь решать задачи, объяснять принятые решения, писать тесты, находить причины ошибок и поддерживать работающий сервис. Наличие темы в конспекте ещё не означает, что я её освоил: знания подтверждаются самостоятельным кодом и практикой.

## Важные оговорки

Команды и фрагменты кода в заметках — учебные примеры, а не готовые production-рецепты. Перед запуском я адаптирую демонстрационные пути, имена таблиц, порты и значения под свой проект. Опасные команды Git и операции удаления сначала проверяю в тестовом репозитории.

Версии Java, Spring Boot, Maven и библиотек меняются. Синтаксис и поведение API я сверяю с официальной документацией версии, которая используется в конкретном проекте.
