# Debugging, Code Review и собеседования

## Отладка
1. Определи фактическое и ожидаемое поведение.
2. Воспроизведи ошибку минимальным сценарием.
3. Я читаю stack trace и я нахожу первое место в моём коде.
4. Я проверяю входные данные, состояние и конфигурацию.
5. Я использую breakpoint, step over/into и watches.
6. Я нахожу первопричину, не маскируй симптом.
7. Я добавляю регрессионный тест.

## Code Review
Проверяй бизнес-логику, обработку ошибок, права доступа, транзакции, конкурентность, SQL, тесты, читаемость, совместимость API и отсутствие секретов.

Хорошее замечание указывает конкретное место, объясняет риск и предлагает направление решения.

## Собеседования
Java: ООП, equals/hashCode, HashMap, Generics, Exceptions, Stream API, JVM, GC, volatile/synchronized.
SQL: JOIN, NULL, WHERE vs HAVING, индексы, ACID, изоляция, EXPLAIN.
Spring: DI, bean lifecycle, proxy, транзакции, JPA, N+1, Security.
Практика: Git, debugging, Docker, тесты.

Ответ: определение → механизм → пример → ограничения → пример из проекта. Не выдумывай коммерческий опыт. Если не знаешь, обозначь это и объясни, как будешь разбираться.

## Как читать stack trace

Я читаю сверху вниз: тип исключения и сообщение показывают, что произошло; первые строки `at ...` показывают цепочку вызовов. Я нахожу первую строку, относящуюся к своему коду, но не игнорируй `Caused by` — первопричина часто находится там. Номер строки помогает открыть точное место.

## Мини-чек-лист перед Pull Request

- Код компилируется и тесты проходят.
- Изменения соответствуют задаче, лишнего нет.
- Нет паролей, токенов и локальных файлов IDE.
- Обработаны ошибки и граничные случаи.
- SQL не создаёт лишних запросов или N+1.
- README/миграции/API-контракт обновлены, если это нужно.
- Коммит и описание PR объясняют смысл изменений.

## Как отвечать на технический вопрос

Не заучивай одно предложение. Объясни: что это → какую проблему решает → как устроено → пример → ограничения/компромиссы. Если не знаешь, честно обозначь границу знаний и расскажи, как проверишь гипотезу.


## Как разбирать незнакомый код

1. Я нахожу точку входа и конфигурацию.
2. Я нахожу контроллер/обработчик нужного запроса.
3. Проследи вызовы service → repository → БД.
4. Посмотри модели запроса/ответа и Entity.
5. Я нахожу тесты — они показывают ожидаемое поведение.
6. Запусти минимальный сценарий и поставь breakpoint.
7. Только после понимания меняй код.
