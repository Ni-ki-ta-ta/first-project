# Maven, Docker и CI/CD

## Maven
Maven — инструмент сборки Java-проектов и управления зависимостями. `pom.xml` описывает проект, библиотеки, плагины и настройки.

```bash
mvn clean
mvn compile
mvn test
mvn package
mvn verify
```
- `clean` — удаляет результаты прошлой сборки (`target`).
- `compile` — компилирует основной код.
- `test` — запускает тесты.
- `package` — собирает JAR/WAR.
- `verify` — выполняет проверки на этапе verify, включая настроенные плагины.

Scope зависимости определяет, на каких этапах она нужна (`compile`, `runtime`, `test` и др.).

## Docker
Docker упаковывает приложение и окружение в контейнер.
- Image — шаблон для создания контейнера.
- Container — запущенный экземпляр image.
- Dockerfile — инструкция сборки image.
- Volume — постоянное хранение данных.
- Network — связь контейнеров.
- Compose — описание приложения из нескольких контейнеров.

```bash
docker build -t task-api .
```
Собирает image `task-api` из Dockerfile текущей папки.

```bash
docker run --rm -p 8080:8080 task-api
```
Запускает контейнер и связывает порт 8080 компьютера с портом 8080 внутри контейнера.

```bash
docker compose up -d
```
Запускает сервисы из compose-файла в фоне.

```bash
docker compose logs -f
```
Показывает логи в режиме наблюдения.

```bash
docker compose down
```
Останавливает и удаляет контейнеры и сеть. Named volumes обычно сохраняются.

`docker compose down -v` удаляет volumes — данные БД могут быть потеряны.

## CI/CD
CI — автоматическая сборка и проверка изменений при push или Pull Request. CD — автоматическая доставка или развёртывание.

Типичный pipeline: checkout → JDK → build → tests → static analysis → image → publish → deploy. Секреты я храню в secret store CI, не в YAML и Git.

## Maven: зависимости и жизненный цикл

`pom.xml` описывает координаты проекта (`groupId`, `artifactId`, `version`), зависимости и плагины. Зависимость обычно имеет scope: `compile` доступна при компиляции и запуске; `runtime` нужна во время выполнения; `test` — для тестов.

Часто используемые команды:
```bash
mvn clean test
mvn clean package
mvn clean verify
mvn dependency:tree
mvn -DskipTests package
```
`-DskipTests` пропускает запуск тестов, но обычно оставляет их компиляцию; `-Dmaven.test.skip=true` может пропустить и компиляцию тестов. Я не использую пропуск тестов как обычный способ «починить» сборку.

## Docker: команды диагностики

```bash
docker ps                  # запущенные контейнеры
docker ps -a               # все контейнеры
docker images              # локальные образы
docker logs -f <container> # логи контейнера
docker exec -it <container> sh  # shell внутри контейнера, если он есть
docker inspect <container> # подробная конфигурация
```
Контейнер — не виртуальная машина: он использует ядро хостовой ОС. Данные нужно хранит в volume или bind mount, если они должны переживать удаление контейнера.

## Dockerfile и Compose

Dockerfile собирает образ приложения; Compose описывает несколько сервисов, сети, volumes и переменные. Не копируй секреты в image через `ENV` или `COPY .env`; передавай их безопасным способом при запуске.

## CI pipeline

Пайплайн должен воспроизводимо собирать проект из чистого checkout. Минимум для Java-проекта: фиксированная версия JDK, `mvn clean verify`, публикация отчётов тестов. Деплой — отдельный контролируемый этап с секретами и возможностью отката.


## Версии и воспроизводимость сборки

Фиксируй версию JDK и ключевых Maven-плагинов. Я не использую плавающие версии зависимостей без понимания последствий. Обновления выполняй осознанно и проверяй тестами. Локальная успешная сборка не заменяет CI на чистом окружении.
