# Java: equals, hashCode, String и неизменяемость

## `==` и `equals`

Для примитивов `==` сравнивает значения. Для ссылочных типов `==` проверяет, указывают ли ссылки на один объект. `equals()` проверяет логическое равенство по правилам класса.

```java
String a = new String("java");
String b = new String("java");
System.out.println(a == b);      // false: разные объекты
System.out.println(a.equals(b)); // true: одинаковое содержимое
```

Я переопределяю `equals()` вместе с `hashCode()`. Контракт требует: если `a.equals(b)` true, то hash code совпадает. Обратное не гарантируется.

Hash-based коллекции используют hash code для поиска области, затем проверяют равенство. Если изменить поля, участвующие в `equals/hashCode`, пока объект лежит в HashSet или используется как ключ HashMap, поиск может перестать работать ожидаемым образом.

## String

`String` неизменяем. Операции, похожие на изменение строки, создают новое значение. Для частого построения строк в цикле использую `StringBuilder`.

```java
StringBuilder result = new StringBuilder();
for (String part : parts) {
    result.append(part).append(',');
}
String value = result.toString();
```

## Неизменяемые объекты

Чтобы сделать объект неизменяемым:
- делаю класс `final`, если наследование не нужно;
- поля делаю `private final`;
- не предоставляю setters;
- копирую изменяемые входные и выходные коллекции;
- не отдаю наружу изменяемые внутренние объекты.

`record` автоматически создаёт методы доступа, `equals`, `hashCode` и `toString`, но не делает глубоко неизменяемыми объекты внутри полей.
