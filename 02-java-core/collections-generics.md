# Collections и Generics

## Зачем нужны коллекции
Коллекции хранят и обрабатывают группы объектов. Интерфейс выбирают по требуемому поведению, реализацию — по характеру операций.

## Основные интерфейсы
- `List` — упорядоченная последовательность, дубликаты разрешены.
- `Set` — уникальные элементы.
- `Queue` — очередь элементов.
- `Deque` — очередь с обоих концов.
- `Map` — пары ключ-значение; не наследуется от Collection.

## Реализации

| Реализация | Что делает | Когда выбирать |
|---|---|---|
| ArrayList | Динамический массив | Список, частый доступ по индексу |
| LinkedList | Двусвязный список | Специфические сценарии; не автоматически быстрее |
| HashSet | Хеш-множество | Проверка уникальности |
| TreeSet | Отсортированное множество | Нужен порядок |
| HashMap | Хеш-таблица | Быстрый поиск по ключу |
| TreeMap | Отсортированная Map | Нужен порядок ключей |
| ArrayDeque | Двусторонняя очередь | Стек или очередь |

## Generics
Generics позволяют задать тип элементов и получить проверку типов компилятором.

```java
List<String> names = new ArrayList<>();
names.add("Alex");
// names.add(42); // ошибка компиляции
```

## Wildcards и PECS
- `? extends T` — источник значений типа T, удобно читать.
- `? super T` — приёмник значений типа T, удобно добавлять.
PECS: Producer Extends, Consumer Super.

## Частые ошибки
- Сравнивать объекты через `==`, когда нужно `equals`.
- Считать, что HashMap сохраняет порядок.
- Менять ключ HashMap после помещения в map.
- Использовать raw types.
- Считать LinkedList быстрее ArrayList только из-за дешёвой вставки: поиск позиции может быть линейным.

## Как выбирать коллекцию

| Нужно | Обычно подходит | Причина |
|---|---|---|
| Список с доступом по индексу | `ArrayList` | Быстрый индексный доступ |
| Уникальность и быстрый contains | `HashSet` | Хеширование |
| Пары ключ-значение | `HashMap` | Поиск по ключу |
| Сортированный набор/ключи | `TreeSet` / `TreeMap` | Порядок по comparator/natural order |
| Очередь или стек | `ArrayDeque` | Операции с концов |
| Потокобезопасная конкурентная Map | `ConcurrentHashMap` | Специальная реализация для нескольких потоков |

Сложность — ориентир, а не гарантия для любого входа. `ArrayList` обычно даёт `O(1)` по индексу; поиск значения — `O(n)`. `HashMap`/`HashSet` обычно дают ожидаемое `O(1)` для базовых операций. `TreeMap`/`TreeSet` обычно `O(log n)`.

## equals и hashCode в HashMap

Хеш помогает выбрать корзину. При совпадении хешей Java дополнительно проверяет равенство ключей. Поэтому контракт `equals`/`hashCode` обязателен. Я не меняю поля, участвующие в `equals`/`hashCode`, пока объект используется как ключ или элемент `HashSet`.

## Generics: ограничения

```java
static <T> T first(List<T> values) {
    return values.get(0);
}
```
`<T>` объявляет параметр типа метода. Generics дают проверку типов на этапе компиляции и уменьшают необходимость casts. В Java они в основном реализованы через type erasure: нельзя, например, написать `new T()` или `new List<String>[10]` обычным способом.

## PECS на примере

```java
static double sum(List<? extends Number> values) { ... }
static void addIntegers(List<? super Integer> values) { ... }
```
`extends` удобно, когда коллекция отдаёт значения типа `T`; `super` — когда в неё записывают значения типа `T`. Из `List<? extends Number>` безопасно читать как `Number`, но нельзя добавить туда конкретный `Integer` (кроме `null`).

## Итерация и изменение коллекции

Не удаляй элементы из коллекции обычным `for-each` через `list.remove`: это может вызвать `ConcurrentModificationException`. Я использую `Iterator.remove`, `removeIf` или формируй новую коллекцию.


## Comparable и Comparator

- `Comparable<T>` задаёт естественный порядок внутри самого класса через `compareTo`.
- `Comparator<T>` задаёт внешний способ сравнения; можно создать несколько разных сортировок.

```java
Comparator<User> byName = Comparator.comparing(User::getName);
users.sort(byName);
```
Если сортировка должна быть стабильной по нескольким полям, я использую `thenComparing`.

## Неизменяемые коллекции

`List.of(...)`, `Set.of(...)`, `Map.of(...)` создают неизменяемые коллекции. Изменяющие операции для них выбросят `UnsupportedOperationException`. Не путай неизменяемую коллекцию с неизменяемыми объектами внутри неё.
