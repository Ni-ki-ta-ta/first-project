# PostgreSQL: индексы, планы, транзакции и эксплуатация

## Индексы

Индекс — дополнительная структура, ускоряющая поиск, но занимающая место и увеличивающая стоимость записи.

- B-tree — равенство, диапазоны и сортировка.
- GIN — составные значения, например массивы и полнотекстовый поиск.
- GiST / SP-GiST — специализированные операторы и типы данных.
- BRIN — большие таблицы, где значения коррелируют с физическим порядком строк.

Индекс полезен не сам по себе: я смотрю на частоту запросов, селективность, порядок столбцов в составном индексе и стоимость поддержки индекса.

## EXPLAIN

```sql
EXPLAIN
SELECT * FROM orders WHERE customer_id = 42;

EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM orders WHERE customer_id = 42;
```

`EXPLAIN` показывает план. `ANALYZE` действительно выполняет запрос. Для запросов, меняющих данные, использую осторожность; можно исследовать внутри транзакции и откатить, но нужно учитывать внешние эффекты и блокировки.

Смотрю на Seq Scan, Index Scan, Bitmap Scan, estimated rows vs actual rows, buffers, sort и join strategy. Seq Scan не всегда плох: для маленькой таблицы или большого процента строк он может быть дешевле индекса.

## ACID

- Atomicity — всё или ничего.
- Consistency — ограничения целостности сохраняются.
- Isolation — параллельные транзакции взаимодействуют по правилам уровня изоляции.
- Durability — подтверждённые изменения сохраняются согласно гарантиям БД.

## MVCC и VACUUM

PostgreSQL использует MVCC: транзакции работают с версиями строк и снимками данных. UPDATE/DELETE могут оставлять старые версии, которые позже очищаются VACUUM, когда они больше не нужны активным транзакциям.

Долгие транзакции могут мешать очистке старых версий и удерживать ресурсы. Autovacuum важен для здоровья базы.

## Транзакции

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
-- При ошибке: ROLLBACK;
```

Транзакция объединяет операции в одну логическую единицу. Я держу её открытой минимально необходимое время.

## Уровни изоляции

PostgreSQL поддерживает READ COMMITTED (по умолчанию), REPEATABLE READ и SERIALIZABLE. READ UNCOMMITTED работает как READ COMMITTED.

- READ COMMITTED: каждый statement получает новый snapshot.
- REPEATABLE READ: транзакция работает с согласованным snapshot; возможны serialization failure в отдельных сценариях.
- SERIALIZABLE: обеспечивает сериализуемое поведение, но приложение должно быть готово повторять транзакции при serialization failure.

## Блокировки и deadlocks

Блокировки защищают согласованность конкурентных изменений. Deadlock возникает, когда транзакции ждут ресурсы друг друга. PostgreSQL обнаруживает deadlock и отменяет одну из транзакций.

Я обновляю записи в согласованном порядке, не держу транзакции долго и обрабатываю ошибки сериализации/блокировок там, где повтор безопасен.

## Constraints

- PRIMARY KEY — уникальный идентификатор и NOT NULL.
- FOREIGN KEY — ссылочная целостность.
- UNIQUE — уникальность.
- NOT NULL — обязательное значение.
- CHECK — проверка условия.

Ограничения БД — последний рубеж целостности, даже если приложение также валидирует данные.
