# Практические проекты для портфолио

Для меня проект ценен не количеством технологий, а тем, насколько хорошо я могу объяснить принятые решения.

## 1. Task Manager API
Java + Spring Boot + PostgreSQL: CRUD задач, фильтрация, сортировка, пагинация, DTO, валидация, единый формат ошибок, миграции, авторизация, unit/integration tests, Docker Compose, README и ER-диаграмма.

## 2. Order Processing
Сервис заказов: статусы, транзакции, конкурентное изменение остатков, идемпотентность; позже — Kafka, Outbox, retry и dead-letter.

## 3. Observability Lab
Сервис со структурированными логами, метриками задержки и ошибок, tracing, нагрузочным тестом и отчётом об оптимизации.

## Критерии готовности проекта
Я считаю проект готовым, когда он собирается понятной командой, тесты запускаются, секреты не попали в репозиторий, а в README есть миграции, примеры API, архитектурные решения и список ограничений. Я могу объяснить каждую существенную часть кода.

## Как не превращать проект в набор технологий

Для каждого проекта я подготавливаю короткий рассказ:
1. Какую проблему решает сервис и кто его пользователь?
2. Какие основные сущности и связи в БД?
3. Как проходит один ключевой запрос от HTTP до БД?
4. Где проверяется вход и права доступа?
5. Что покрыто тестами и почему выбраны именно эти тесты?
6. Какие ошибки/ограничения известны и что улучшил бы дальше?

Лучше один небольшой законченный сервис, который я понимаю построчно, чем большой проект с Kafka, Redis и Kubernetes, смысл которых я пока не могу объяснить.
