# Production: наблюдаемость, производительность и безопасность

## Observability
Наблюдаемость помогает понять состояние приложения по внешним данным:
- Logs — отдельные события с контекстом.
- Metrics — числовые показатели во времени.
- Traces — путь запроса через компоненты.

Полезные метрики: throughput, latency p50/p95/p99, error rate, CPU, память, очереди, соединения БД, heap и паузы GC.

## Логи
Я использую DEBUG, INFO, WARN, ERROR по назначению. Добавляй request/trace ID. Не записывай пароли, токены и чувствительные данные.

## Надёжность
- Таймауты для сетевых вызовов.
- Ограниченные retry только для временных ошибок.
- Backoff и jitter уменьшают синхронные повторные нагрузки.
- Graceful shutdown позволяет завершить текущую работу.
- Health/readiness checks показывают состояние приложения.
- Резервные копии нужно проверять восстановлением.

## Производительность
Я измеряю проблему → я нахожу узкое место → формулирую гипотезу → я изменяю один фактор → сравни на сопоставимой нагрузке → я проверяю корректность. Не оптимизируй на глаз.

## Безопасность
Минимальные привилегии, серверная проверка прав, параметризованные SQL-запросы, безопасное хранение секретов, TLS и обновление зависимостей.

Изучаю OWASP Top 10, SQL Injection, XSS, CSRF, SSRF и Broken Access Control.

## SLI, SLO и SLA

- SLI — измеряемый показатель качества (например, доля успешных запросов или p95 latency).
- SLO — целевое значение SLI внутри периода.
- SLA — формальное обязательство перед клиентом, часто с последствиями при нарушении.

## Таймауты и retry

У каждого сетевого вызова должен быть осмысленный timeout. Повторяй только ошибки, которые могут временно исчезнуть; ограничивай число попыток и общий срок. Exponential backoff с jitter помогает не перегружать зависимость синхронными повторами. Повтор небезопасной операции требует идемпотентности.

## Безопасность по слоям

- Валидация входных данных не заменяет авторизацию.
- Проверяй права на каждый ресурс на сервере.
- Я использую least privilege для пользователя БД и сервисных аккаунтов.
- Я не храню секреты в репозитории, образе контейнера и логах.
- Обновляй зависимости и следи за известными уязвимостями.
- Резервная копия полезна только если восстановление проверено.

## Инцидент

Зафиксируй время, симптомы, масштаб и последние изменения. Сначала восстанови сервис безопасным способом, затем я нахожу первопричину. После инцидента я добавляю мониторинг, тест или изменение процесса, чтобы снизить шанс повторения.
