# HTTP и REST API

## HTTP
HTTP — протокол обмена запросами и ответами между клиентом и сервером. Запрос содержит метод, путь, заголовки и иногда тело. Ответ содержит статус, заголовки и иногда тело.

## Методы
- GET — получить представление ресурса; безопасный метод, не должен менять состояние.
- POST — передать данные на обработку; часто создание ресурса.
- PUT — заменить представление ресурса; по семантике идемпотентен.
- PATCH — частично я изменяють ресурс; идемпотентность зависит от операции.
- DELETE — удалить ресурс; идемпотентен по семантике.

Идемпотентность означает одинаковый эффект повторного выполнения, а не обязательно одинаковый ответ.

## Статусы

| Код | Значение | Применение |
|---|---|---|
| 200 | OK | Успешный запрос с ответом |
| 201 | Created | Ресурс создан |
| 204 | No Content | Успешно, тело не нужно |
| 400 | Bad Request | Некорректный запрос |
| 401 | Unauthorized | Нет корректной аутентификации |
| 403 | Forbidden | Пользователь известен, но доступа нет |
| 404 | Not Found | Ресурс не найден |
| 409 | Conflict | Конфликт с текущим состоянием |
| 500 | Internal Server Error | Неожиданная ошибка сервера |

## Пример
```http
POST /api/tasks HTTP/1.1
Content-Type: application/json

{"title":"Review PR","description":"Check tests"}
```
При создании можно вернуть `201 Created` и заголовок `Location: /api/tasks/123`.

## REST
REST — архитектурный стиль: ресурсы имеют адреса, операции используют семантику HTTP, интерфейс согласован.

Хороший API валидирует вход, возвращает единый формат ошибок, поддерживает пагинацию, документирует схемы и не раскрывает stack trace клиенту.

## Заголовки, тело и content negotiation

- `Content-Type` описывает формат тела запроса/ответа, например `application/json`.
- `Accept` сообщает, какие форматы ответа клиент готов принять.
- `Authorization` передаёт данные аутентификации; не логируй секреты из него.
- `Location` часто указывает URI созданного ресурса после `201 Created`.

## Безопасность и идемпотентность методов

Safe method не должен менять состояние сервера по смыслу. Idempotent method при повторе имеет тот же предполагаемый эффект, хотя ответы и логи могут отличаться. `POST` обычно не идемпотентен; для безопасного повтора создания применяют idempotency key или другой контракт.

## Пагинация и ошибки

Большие коллекции отдавай страницами или курсорами. Зафиксируй параметры `page`, `size`, `sort`, максимальный размер страницы и стабильный порядок сортировки. Ошибка API должна содержать понятный код/сообщение для клиента, но не stack trace и внутренние детали.

## REST — не просто JSON

REST — архитектурный стиль с ограничениями (в том числе единый интерфейс, stateless, cacheability). Наличие URL и JSON само по себе не делает API RESTful. В обычной работе важнее последовательная семантика ресурсов и HTTP.
