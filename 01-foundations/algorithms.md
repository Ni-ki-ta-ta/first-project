# Алгоритмы и структуры данных

## Что такое алгоритм

Алгоритм — последовательность действий для решения задачи. Хороший алгоритм не только даёт правильный результат, но и разумно использует время и память.

## Big O

Big O описывает, как растёт объём работы при увеличении входных данных. Это не точное время в секундах.

| Сложность | Пример | Как растёт работа |
|---|---|---|
| O(1) | Доступ к элементу массива по индексу | Не зависит от размера |
| O(log n) | Бинарный поиск | На каждом шаге область примерно вдвое меньше |
| O(n) | Один проход по списку | Растёт пропорционально n |
| O(n log n) | Эффективные сортировки сравнением | Чуть быстрее квадратичного роста |
| O(n²) | Сравнение каждой пары | При удвоении n работа примерно в 4 раза больше |

При оценке учитывай время и дополнительную память.

## Основные структуры

### Array / ArrayList
Я хранют элементы последовательно. Доступ по индексу быстрый. Вставка в середину требует сдвига элементов.

### LinkedList
Элементы связаны ссылками. Чтобы найти элемент по индексу, обычно нужно пройти по списку. Поэтому LinkedList не автоматически быстрее ArrayList.

### HashMap
Я хранют пары ключ-значение. Хеш ключа помогает быстро найти корзину. Средняя сложность get/put обычно O(1), но зависит от распределения хешей и реализации.

### HashSet
Я хранют уникальные элементы. Проверка наличия обычно быстрая. Уникальность определяется через equals и hashCode.

### TreeMap / TreeSet
Хранят элементы в отсортированном порядке. Основные операции обычно O(log n).

### Queue / Deque
Queue — очередь обработки. Deque позволяет добавлять и извлекать элементы с обоих концов. ArrayDeque часто подходит для стека и очереди.

## Частые алгоритмические приёмы

- Линейный поиск — проверить элементы по очереди.
- Бинарный поиск — искать в отсортированных данных, деля диапазон пополам.
- Два указателя — двигать два индекса навстречу или в одном направлении.
- Sliding window — поддерживать окно элементов и сдвигать его.
- Частотный словарь — считать элементы через Map.
- BFS — обход графа по уровням.
- DFS — обход в глубину.

## Как решать задачу

1. Перескажи условие своими словами.
2. Уточни ограничения и крайние случаи.
3. Придумай простой корректный алгоритм.
4. Оцени его сложность.
5. Улучши только если это необходимо.
6. Я проверяю пустой ввод, один элемент, дубликаты и большие данные.

## Как оценивать сложность точнее

- Последовательные циклы обычно складывают: `O(n) + O(n) = O(n)`.
- Вложенные циклы по одним и тем же `n` элементам обычно дают `O(n²)`.
- Если на каждом шаге размер задачи делится пополам, часто получается `O(log n)`.
- Для двух разных размеров я использую обе переменные: например, `O(n * m)`.
- Амортизированная сложность усредняет стоимость серии операций: добавление в `ArrayList` обычно амортизированно `O(1)`, хотя отдельное расширение массива требует `O(n)`.

## Частые ошибки

- Бинарный поиск работает корректно только при подходящем порядке данных и корректных границах.
- `HashMap` даёт ожидаемое быстрое обращение, но не гарантирует `O(1)` в каждом случае.
- Рекурсия расходует стек вызовов; слишком глубокая рекурсия может привести к `StackOverflowError`.
- Сначала добейся корректности простым решением, затем измеряй и оптимизируй.

## Мини-шаблон решения задачи

1. Я записываю вход и ожидаемый выход.
2. Я проверяю ограничения: сколько элементов, могут ли быть `null`, отрицательные числа, дубликаты?
3. Придумай простое решение и оцени `O`.
4. Подбери структуру данных под операции.
5. Я проверяю граничные случаи и сложность памяти.
